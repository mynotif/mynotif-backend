# Private prescription summaries v2 — M03-B

Normative [mobile contract](https://github.com/mynotif/ordopro_mobile/blob/main/docs/agentic/work/OP-M03/contracts-v2.md), confirmed design PR #73. Backend #269 depends on #268 and#267. Mobile #70/#71 and parent #10 remain open. This is backend code/evidence, without an Android adapter, document flow, real data or deployment.

Two GET paths: `/api/v2/patients/{patient_id}/prescriptions/` and `/api/v2/patients/{patient_id}/prescriptions/{prescription_id}/`. The same five fields appear in list results and detail: id, patient_id, prescribing_doctor, start_date, end_date. Dates are their exact source values; no clinical calculation or validation changes. No email, image/PDF, signed URL, OCR, is_valid or expiring_soon. Queries select these columns only; storage/S3/signing helpers are not invoked. v1 serializers/document endpoints are preserved separately.

M02 opaque Bearer only; then resolve patient within current Nurse associations, then prescription within that patient, then validate query. A missing Nurse yields 404 and is never created by a read. Staff/admin has no implicit access. Foreign/nonexistent patients and prescriptions, including a prescription owned by another authorized patient, use identical 404 not_found JSON. IDs must be positive integers; malformed and out-of-database-range paths are 404 after authentication, with no global existence query. Leading-zero positive ID paths are accepted as the same integer; query integer syntax remains strict.

Collection accepts only unique page/page_size (defaults 1/20, size 1…100, page≤2147483647); rejects search, fields, ordering, patient, unknown or duplicate parameters. Order end_date DESC, id DESC. Uses the [common envelope/errors/cache](reads-v2.md). Empty page 1 is 200 with count 0 and null neighbors; out-of-range page 404 page_not_found. Detail accepts no query parameters at all. Rights precede bad-query errors on both nested routes.

HEAD has GET rights/status/headers without body. OPTIONS checks patient and prescription rights and query, then returns only allowed_methods GET/HEAD/OPTIONS. Valid-route mutations are 405 after authentication. Private/no-store and Pragma:no-cache apply to controlled successes/errors; no ETag/304. Token auth, absent/invalid/expired/revoked Bearers are 401 with WWW-Authenticate:Bearer. No new operational throttle rate.

OpenAPI adds closed PrescriptionSummary and PrescriptionPage, Bearer security, integer positive path IDs and explicit page query parameters on the collection. The GET descriptions document HEAD/OPTIONS and cache. Tests prove exact schema, source dates, SQL limits/query counts, A/B and per-patient isolation, no storage calls, auth/query/cache and route registration using synthetic fixtures. The reusable loopback proof script covers these routes once registered. See Verify for actual commands/results/SHA and limitations.

Application/Gunicorn privacy safeguards come from #268. Real proxy/App Runner/hosting logs remain unqualified; no data may be used before independent upstream query/identifier redaction checks. Tests do not validate future mobile behavior after a second 401 following refresh. Remove v2 routes for rollback, keep v1 and normalization columns; no merge or production migration is authorized here.
